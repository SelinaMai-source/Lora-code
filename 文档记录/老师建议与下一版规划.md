# 老师建议 vs 当前最佳 Ours 方法 — 分析与下一版规划

**撰写日期**：2026-06-12  
**分析基准**：`v6_sota_2`（当前最佳，seg18 seen_avg=0.350）  
**对照实验**：`v4_sota_39`（历史最佳，0.352）、`v7_sota_1`（已早停，seg5 seen_avg=0.197）  
**代码锚点**：`core/methods/router.py`、`drift_detector.py`、`overlap_loss.py`、`core/train.py`

---

## 0. 当前瓶颈诊断（数据驱动）

### 0.1 SOTA 目标差距（seg18）

| 指标 | 目标 | v6_sota_2 | v4_sota_39 | 主要瓶颈？ |
|------|------|-----------|------------|-----------|
| seen_avg_score | ≥0.600 | **0.350** | 0.352 | ✅ 核心 |
| seen_avg_task_aware | ≥0.600 | 0.386 | 0.383 | ✅ |
| forgetting | ≤0.033 | 0.057 | 0.050 | 次要 |
| token_f1_mean | ≥0.600 | 0.422 | 0.435 | ✅ |
| lcs_overlap_mean | ≥0.600 | 0.445 | 0.475 | ✅ |
| **oracle_agreement** | — | **0.374** | **0.488** | ✅ 路由天花板 |

### 0.2 关键观察

1. **路由准确率是硬天花板，但不是唯一瓶颈**：v4_39 的 oracle 约 0.49，seen_avg 仍仅 ~0.35；说明「路由对了」也不足以到 0.6，分支单任务容量（1ep/50 样本）与生成质量是第二瓶颈。
2. **v6_sota_2 早期路由极好、后期衰减**：seg3–4 oracle≈0.98，seg12+ 降至 0.39–0.42；原型在分支增多后区分度下降（`overlap_mean_cosine` 升至 0.80–0.90）。
3. **soft blend 是双刃剑（v6_sota_3–6 证伪实验）**：
   - 5ep + soft blend（v6_3）→ seg4 早停，混合摧毁特化分支；
   - 硬路由无对冲（v6_4）→ seg3 早停；
   - 3ep + soft blend（v6_5）仍失败；
   - 纯 NLL 硬仲裁 + 3ep（v6_6）→ seg3 seen=0.05。
4. **v7_sota_1 失败模式**：seg4 seen=0.32（接近 v6_2 的 0.34），seg5 崩塌至 0.197；seg3 单段 forgetting 飙至 0.70。校准+NLL 仲裁在分支数≥3 时可能过度硬路由，破坏 soft top-3 的缓冲收益。
5. **现有 anti-overlap 正则偏弱**：训练期 `overlap.beta=0.05`，但 eval 期 `overlap_mean_cosine` 仍达 0.87+，说明参数空间正交未有效传导到路由/混合层。

**结论**：首要瓶颈是 **oracle_agreement × soft-blend 干扰** 的复合效应；次要瓶颈是 **单分支 1ep 微调容量** 不足以支撑 0.6 生成指标。

## 1. 老师建议一：变点 / 课程学习 / 元学习

### 1.1 与现有代码的映射

| 子建议 | 已有实现 | 缺失 |
|--------|----------|------|
| Anchor-set 自适应变点 | `DriftDetector`：core/probe 双层 anchor + CUSUM + 校准窗口（`drift_detector.py`） | 无任务级难度感知的变点阈值 |
| 课程学习 easy→hard | `build_anchor_set` 中 `curriculum_strategy: easy_core_hard_probe`（按文本复杂度排序 anchor） | **训练流**无课程；仅 anchor 监控用 |
| 元学习（anchor 上学能力再下游微调） | `meta_threshold_enabled` 配置项存在但未启用 | 无 MAML/Reptile 式 inner-loop；无 anchor 元训练 |

相关配置（v6_sota_2）：

```yaml
drift:
  curriculum_strategy: easy_core_hard_probe  # 仅影响 anchor core/probe 划分
  meta_threshold_enabled: false
```

### 1.2 增量采纳能否提升 toward 0.6？

- **短期（v7/v8，1ep 预算不变）**：预期 **+0.02~0.05 seen_avg**，难破 0.4 天花板。
- **理由**：InstrDialog 每 segment 仅 50 train / 10 eval，课程重排样本对 1ep 影响有限；元学习需额外 forward 预算，与已验证的「1ep/batch=2」协议冲突。
- **中期**：若允许 anchor 上 2–3 step 元适配 + 下游 1ep，可能改善早期分支质量，但需单独消融证明公平性。

### 1.3 具体版本提案

**v8_sota_3（课程变点，单点变更）**  
- 假设：probe 侧逐步引入更难 anchor（segment-index 调 `probe_difficulty_ratio`），使变点触发更「稳」、减少误 spawn。  
- 改动：仅 `drift_detector.py` + yaml；`train.py` 不动。  
- 基座：v6_sota_2（非 v7_1）。

### 1.4 新颖性 vs 文献

| 文献 | 关系 |
|------|------|
| CL-MoE / DEMix | 任务边界已知或离线聚类；我们是 **无任务 ID 流式变点** |
| Curriculum CL (Wang et al.) | 常见样本难度课程；我们可主张 **monitoring-set curriculum** |
| MAML-LoRA | 元学习 LoRA 初始化；我们若做需强调 **anchor-only、无标签** 的公平设定 |
| CUSUM / Page-Hinkley | 经典变点；我们的 **core-probe 双阈值守卫** 是差异化点 |

### 1.5 风险

- 变点更保守 → 分支不足，单分支过载遗忘上升；
- 元学习算力翻倍，可能触发与 v6_3 类似的「过训练破坏特化」；
- 课程定义依赖启发式复杂度（`_anchor_complexity`），与真实任务难度未必对齐。

## 2. 老师建议二：LoRA Bank + Routing 统一框架

### 2.1 与现有代码的映射

| 模块 | 实现位置 | 当前状态 |
|------|----------|----------|
| LoRA Bank | `core/methods/lora_bank.py` | spawn/freeze/max_branches/merge |
| 漂移触发 spawn | `train.py` L840–843 | `spawn_on_drift` + `freeze_old_branches` |
| 原型路由 | `router.py` `routing_backend: prototype` | NLL 伪标签 → EMA 原型 → 余弦打分 |
| 评测混合 | `evaluate.py` soft top-3 + optional NLL 仲裁 | 与训练逻辑分离配置 |
| Anti-overlap | `overlap_loss.py` | 训练期激活/权重正交，**未约束路由权重** |

**缺失**：三者缺少统一的「记忆—路由—推理」数学表述；论文读起来是模块堆叠而非一个框架。

### 2.2 增量采纳能否提升指标？

- 统一叙事 **不直接改数字**，但可指导工程：将「spawn 时机」「原型更新」「混合权重」绑在同一状态机下，减少 v6/v7 各自为战的调参失败。
- 若实现 **Bank–Router 协同损失**（spawn 时初始化原型 = 当前 drift 窗口特征质心），预期 oracle **+0.03~0.08**。

### 2.3 具体版本提案

**v8_sota_4（协同初始化，单点变更）**  
- spawn 新分支时，用触发变点前后 anchor 特征均值初始化该分支原型（而非等训练后 NLL 伪标签）；其余同 v6_sota_2。  
- 统一故事点：「变点检测 → 分支出生 → 原型锚定」一条链。

### 2.4 新颖性 vs 文献

- **MoE-Adapters / LoraHub**：外挂路由，无流式变点；
- **O-LoRA / LFPT5**：正交子空间，无 bank+routing；
- **S-Prompts / HiDe-Prompt**：任务原型，需任务边界；
- **我们的定位**：Task-agnostic **Drift-Spawning Bank** + **Frozen-Coherent Prototype Router** 闭环。

### 2.5 风险

- 框架化重构范围大，违反「单版本单变更」若一次改太多；
- 协同损失调不好会引入 v7_1 式 seg 初期不稳定。

## 3. 老师建议三：正交损失（第三贡献，重点）

### 3.1 与现有代码的映射

| 类型 | 已有 | 缺失 |
|------|------|------|
| 参数空间正交 | `compute_orthogonal_weight_loss`（`overlap_loss.py`），legacy router head `ortho_loss` | 对 **frozen 分支** 梯度被 detach，主要约束 active 分支 |
| 激活空间反重叠 | `compute_overlap_loss_torch`（库仑势） | eval 期 cosine 仍 0.87+，正则过弱或未作用于混合路径 |
| **路由权重正交** | 无 | 老师明确指出：soft blend 时防止 LoRA 重叠混合 |

### 3.2 与 v6_sota_3–5 失败诊断的直接关联（强调）

```
v6_sota_3: 5ep + soft blend → 特化分支被混合抹平
v6_sota_4: hard route only  → 路由错误无缓冲，seg3 崩溃
v6_sota_5: 3ep + soft blend → 仍抹平
```

**根因链条**：多分支 LoRA 在参数空间高度重叠（overlap_mean_cosine≈0.9）→ soft top-3 加权求和时，**错误分支的干扰分量无法相消** → 即使 oracle 50%，有效利用率更低 → seen_avg 卡在 0.35。

老师建议的「routing weights 正交化」 precisely 针对此：**混合权重应投影到分支正交补空间，或惩罚高相似分支同时获得高权重**。

### 3.3 增量采纳能否提升 toward 0.6？

- **预期影响最大**：seen_avg **+0.05~0.15**（若 orthogonal blend 将有效 oracle 利用率从 ~50% 提到 ~65%）。
- 不增加训练 epoch，仅改 eval 混合策略 + 可选轻量训练正则，符合 v6_2 预算协议。

### 3.4 具体版本提案

**v8_sota_1（首选）：Orthogonal Soft Routing（评测期单点变更）**  
- 基座：**v6_sota_2**（回退 v7_1 的校准+NLL 仲裁）。  
- 改动：在 `evaluate.py` soft blend 前，对 top-k 分支权重 \(w_i\) 施加  
  \(\tilde{w}_i \propto w_i \cdot \exp(-\lambda \sum_{j \neq i} \cos(\theta_{ij}))\)，  
  或 Gram-Schmidt 投影：混合增量 \(\Delta W = \sum_i \tilde{w}_i \Delta W_i\) 其中 \(\tilde{w}\) 经正交化。  
- 配置：`router.orthogonal_blend: true`, `orthogonal_blend_lambda: 0.5`（单超参）。  
- 假设：抑制高相似分支同时参与混合，保留 v6_2 的 soft 缓冲，避免 v6_4 硬路由脆断。

**v8_sota_2（训练期补充）：Routing-aware Orthogonal Loss**  
- 在 `compute_anti_overlap_training_loss` 增加项：对当前 batch 路由分布 \(p\) 惩罚 \(\sum_{i<j} p_i p_j \cos(v_i, v_j)\)。  
- 单点变更，beta 从 0.05→0.08 仅用于新项。

### 3.5 新颖性 vs 文献

| 工作 | 区别 |
|------|------|
| O-LoRA | 序列任务子空间正交，**无 MoE 式混合** |
| LoRA-MoE | 路由学习，无正交混合约束 |
| Model Soup / WiSE-FT | 假设同质 checkpoint 可平均；我们证明 **frozen-specialized LoRA 不可任意混合** |
| DEMix perplexity routing | 困惑度路由，无参数正交 |
| **我们** | **首个在 CL-LoRA-bank 评测期对混合权重做相似度门控**，连接 v6 失败实证 |

### 3.6 风险

- 正交化过度 → 退化为单分支硬路由（重现 v6_4）；
- 需 GPU 额外算相似度（top-k=3 可忽略）；
- 若分支本就应协同（相近任务），正交门控可能伤 recall。

## 6. 统一框架叙事（论文一段）

> 我们提出 **DAPR**（*Drift-Anchored Prototype Routing*）——一个面向无任务边界指令流式持续学习的统一框架。固定 anchor 集上的双层监控（core/probe）驱动 **CUSUM 变点检测**，在统计显著漂移时向 **LoRA Bank** 注入并冻结新分支，以容量扩展替代梯度覆盖；每个分支伴随一个由 teacher-forced NLL 自一致伪标签维护的 **漂移锚定原型**，且原型随分支同步冻结，从而保证「参数记忆」与「路由记忆」一致。推理阶段，原型余弦路由给出 top-k 候选后，经 **正交门控软混合** 聚合专家，避免高度重叠的 frozen adapter 在参数空间相互污染——这一设计直接由我们关于「专化分支不可任意 model-soup」的实证消融（v6_sota_3–5）所动机。训练期辅以分支间激活/权重反重叠正则，使整个系统形成「检测 → 分裂 → 专化 → 正交检索」闭环，而非独立的 drift、bank、router 三模块拼接。
